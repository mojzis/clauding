Use only these tags. Add new ones here, in the same change, with a one-line meaning.
Applies to `docs/**` and `content/**`.

- `meta`: about the docs themselves
- `architecture`: structure, boundaries, data flow
- `dev`: local setup, tooling, CI
- `qa`: tests, checks, oracles, what "correct" means
- `principle`: a manifesto principle page (one per rule)
- `rules`: the versioned rules text inlined into repos
- `adoption`: getting a repo onto the rules: catch-up prompt, scaffold, upgrades
- `site`: the published site: build, pages, `llms.txt`
- `adr`: decision records as a practice
- `papercuts`: friction logging as a practice
- `knowledge`: small linked files, frontmatter, tags
- `freshness`: keeping docs true to the code
- `tooling`: the planned checker CLI
- `evolving`: practices on trial, not yet in the rules
- `handoff`: where a session left off, what the next one picks up
- `ideas`: parked ideas, captured mid-task
